# CBCL Companion — 검사 결과 안내 도우미 (PoC)

- 공개 저장소: https://github.com/KrSuma/cbcl-companion
- 라이브 데모: https://cbcl-companion-3c7a7e121cbb.herokuapp.com (접근 비밀번호는 제출 메일에 기재. Eco dyno라 첫 접속 시 수 초 대기)

**무엇을 만드나.** K-CBCL 결과 보고서와 함께 제공되는 보호자용 AI 도우미 두 가지. (A) 보고서를 보호자 언어로 풀어 주는 **쉬운 말 해설**, (B) 상담 대기 기간에 질문을 받고 진단·치료 질문은 상담사에게 넘기는 **상담 전 질문 챗봇**과 상담사 전달 메모.

**어떻게 만드나.** AI는 숫자를 해석하지 않음. 보고서에 인쇄된 기준으로 코드가 범위를 분류하고, AI는 분류된 사실만 쉬운 말로 옮기며, 세 겹의 가드레일이 "보고서에 없는 말"을 걸러냄. 가드 실패 시 규칙만으로 만든 템플릿으로 대체.

**무엇을 달성하나.** 보고서 수령부터 상담까지 며칠간 쌓이는 "용어를 모르겠다 → 심각한 건가 → 불안"을 줄임. 그 결과 지원 문의와 상담 이탈(no-show)을 줄이고, 상담사가 보호자의 불안 지점을 알고 통화를 시작하게 함. 진단·처방은 어떤 경우에도 AI가 하지 않음.

## 기능

| 기능 | 내용 |
|---|---|
| A. 쉬운 말 해설 | 임상 범위 해당 여부를 정직하게 말하는 첫 줄 → 선별 검사이며 진단이 아니라는 설명 → 용어 풀이("또래 100명 중 몇 번째") → 종합 지표 → 지켜볼 영역(보호자 의견과 연결) → 미실시 척도 → 상담 전 준비와 상담사에게 물어볼 질문 |
| B. 상담 전 질문 챗봇 | 같은 facts 안에서만 답함. 질문을 여섯 유형(용어·수치 / 불안·안심 / 임상 / 준비·생활 / 일정 / 위기)으로 내부 분류해 다르게 처리. 임상 질문은 인정 → 선별 검사로는 답할 수 없는 이유 → 상담사가 다룸 → **메모 기록**. 자해·학대 신호는 LLM을 거치지 않고 고정 위기 안내(112, 1577-0199) |
| 상담사 전달 메모 | 대화 종료 시 자동 생성. 보호자가 무엇을 두려워하는지, 어떤 진단 질문을 했는지, 관심 주제를 한 장에 담아 상담사가 통화 전에 읽음 |

## 설계: LLM은 숫자를 해석하지 않음

```
보고서(PDF/JSON) ─▶ [규칙 계층] 점수 → 범위 분류 → facts(JSON)   ← 보고서에 인쇄된 기준, 코드가 결정
                          ▼
                    [LLM] facts를 쉬운 말로 옮김 (구조화 출력)
                          ▼
                    [가드] 금지어 → 숫자 출처 → LLM 심사(소형 모델)   ← 실패 시 재시도 1회 → 템플릿 폴백
                          ▼
                    보호자 안내문 / 대화 답변 / 상담사 전달 메모
```

| LLM이 하는 일 | LLM이 하지 않는 일 (코드가 함) |
|---|---|
| 분류된 facts를 쉬운 한국어로 재서술, 보호자 의견과 척도 연결 | T점수를 정상/준임상/임상으로 분류, 플래그할 척도 결정, 백분위 환산 |
| 질문 유형 분류, 불안 수준 추정, 상담사 메모 한 줄 | 위기 신호 감지(정규식, LLM 이전), 출력 검증, 폴백 결정 |

- **임상 경계** (`prompts.py`): 진단명 긍정·부정 금지("ADHD는 아닙니다"도 금지), 치료·약물·병원 권유 금지, facts 밖 수치·원인 추정 금지, 거짓 안심 금지.
- **가드** (`guard.py`): 금지어 정규식 → 출력의 모든 숫자가 facts에 존재하는지 → Haiku 심사. 해설은 세 가지 항상, 대화는 보호자가 먼저 꺼낸 진단·약물 단어를 되풀이한 턴에만 심사 호출(`ECHO_GROUPS`).
- **위기 신호** (`chat.py`): 정규식 사전검사로 LLM 이전에 차단.

## 실행 방법

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[app,dev]"
cp .env.example .env                 # ANTHROPIC_API_KEY 입력

cbcl facts                           # LLM이 받는 facts (API 불필요)
cbcl explain --template              # 템플릿 폴백 (API 불필요)
cbcl explain --out outputs/guide.md  # 기능 A
cbcl chat                            # 기능 B (대화형)
cbcl chat --ask "준임상이 무슨 뜻이에요?" --ask "주의집중이 95%면 ADHD 아니에요?"
cbcl --report path/to/report.pdf explain   # PDF 입력 (제공된 보고서 템플릿 기준)
cbcl eval --model claude-haiku-5-5   # 26케이스 가드레일 평가, 모델 교체 비교
streamlit run app/streamlit_app.py   # 데모 UI: 원본 보고서 → 쉬운 말 해설 → 상담 전 질문 챗봇 → 내부 공유용
pytest                               # 단위 테스트 10개 (API 불필요)
```

Heroku 배포: `Procfile`, `.python-version`, `requirements.txt` 포함. `heroku config:set ANTHROPIC_API_KEY=... APP_PASSWORD=... -a <app> && git push heroku main`.

## 사용 모델 / API

Anthropic Claude API, Python SDK `anthropic`, Messages API + 구조화 출력(`messages.parse`).

| 역할 | 모델 · 빈도 | 이유 |
|---|---|---|
| 해설 생성 (A) | `claude-opus-5-5` · 보호자당 1회 | 보호자가 처음 읽는 문장이 신뢰를 좌우. 가장 드문 호출에 가장 좋은 모델 |
| 대화 (B) | `claude-opus-5-5`, effort low · 약 10턴 | 시스템 프롬프트와 facts를 프롬프트 캐시로 고정해 턴당 입력 비용 10분의 1 |
| 심사 | `claude-haiku-5-5` · 해설 항상, 대화 되풀이 턴 | 예/아니오 분류. 저가 모델로 충분 |

선택 기준: 임상·적대적·위기 14케이스는 어떤 티어든 100% 통과해야 하고, 그 위에서 가장 싼 티어를 고름. 아래 결과 기준 대화는 Haiku 5.5로 낮출 후보.

| 대화 1턴 (Opus 5.5, effort low, 캐시 적중) | 15~22원 ($0.011~0.016) |

## 범위 밖과 알려진 한계

- 진단·치료·약물·원인에 대한 어떤 판단(상담사 영역), 원본 보고서의 수정이나 대체, 상담사 화면 통합, 대기 기간 자동 체크인은 범위 밖.
- "이해하면 덜 불안하다"는 가설은 보호자 검증 전. 심사 모델은 경계선 표현에서 0~1건/26케이스 오탐. 척도-숫자 연결 오류는 숫자 가드가 잡지 못하고 심사가 잡음.
- 위기 정규식은 "때려"에서 아이가 맞는 경우와 아이가 동생을 때리는 경우를 구분하지 못함(상담사 검토 필요). 백분위는 정규분포 근사. PDF 파서는 제공된 보고서 템플릿 전용(운영 경로는 JSON).
